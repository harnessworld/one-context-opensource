# Project Rules — one-context workspace

These rules are the canonical constraint surface for every AI coding tool in
this workspace. They are inlined verbatim into each tool's startup context by
`onecxt adapt` — the generated copies are read-only mirrors of this file.

## Canonical sources

- Single source of truth (SoT) lives in tracked, hand-written files:
  `meta/*.yaml` (repos, workspaces, agents, profiles), `.onecxt/RULES.md`,
  `knowledge/01_Compiled/**`, and `skills/<name>/SKILL.md`.
- Files carrying the generated marker (`GENERATED by onecxt adapt` …) are
  build outputs. Never hand-edit them; change the SoT and rerun
  `onecxt adapt` instead.
- `AGENTS.md` at the repository root is generated the same way. Regenerate it
  after changing the project overview or this rules file.

## Workflow

- Validate manifests before and after manifest or knowledge edits:
  `onecxt doctor`. Errors must be fixed; warnings should be acknowledged.
- Feature work flows through `features/`: spec → tech design → implement →
  test report → delivery note. Use `features/_template/` as the starting
  point and keep `features/INDEX.md` in sync (doctor enforces the index).
- Changes stay repository-scoped. Before touching shared files, confirm the
  change belongs to the current feature or is an explicit maintenance task.

## Safety and scope

- Never add secrets, credentials, tokens, or private keys to the workspace.
  Per-machine settings belong in git-ignored `.onecxt/local.yaml` or `.env`
  files, never in tracked manifests.
- Do not invent provider-specific endpoints, proxy routes, or account-level
  configuration in shared files. Such settings are machine-local by contract.
- Destructive operations (deleting branches, force pushes, `--force`
  regenerations) require explicit human approval.
- Keep framework implementation under `packages/one-context/`; business code
  belongs in repositories registered in `meta/repos.yaml`.
- Keep generated paths inside the workspace root.

## Knowledge hygiene

- Knowledge notes marked private via frontmatter (`visibility: private`) are
  excluded from context exports and knowledge-graph scans. Respect that
  boundary when summarizing or linking.
- Cross-file references use root-relative `@path/to/file.md` syntax inside
  `knowledge/`, `docs/`, and `features/`; dangling references fail doctor
  checks.

## Communication style

- Report work in plain language: what changed, what was verified, what is
  left. Prefer short structured summaries over long prose.
