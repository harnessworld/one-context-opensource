# knowledge/ — workspace knowledge base

This directory is **yours**. It ships with a small framework-neutral example
tree so `onecxt doctor`, `onecxt adapt`, and context exports have valid
sources to consume; replace or extend it with your own notes.

## Ownership

- Everything under `knowledge/` is regular tracked content of *this*
  repository. There are no submodule assumptions here.
- If you prefer to keep your own knowledge in a separate repository, you can
  later replace this directory with your own git submodule or a synced
  checkout — one-context only cares that the paths referenced from
  `meta/workspaces.yaml` and `meta/agents.yaml` resolve inside the workspace
  root.
- Canonical knowledge referenced by the generated `AGENTS.md` lives at
  `knowledge/01_Compiled/one-context/` in this sample.

## Example layout

```text
knowledge/
├── README.md                          ← this file
└── 01_Compiled/one-context/
    ├── project-overview.md            ← inlined into generated AGENTS.md
    └── conventions.md                 ← linked from sample agents/workspaces
```

The numeric prefix (`01_`) is just a convention; organize by whatever
taxonomy fits your work. Agents and workspaces reference files **or whole
directories** (directory entries expand to every contained `.md`).

## Privacy frontmatter

Any Markdown file under `knowledge/` can opt out of automated collection by
declaring privacy in its YAML frontmatter:

```markdown
---
visibility: private
---
# My private note
```

Effects (content-level only):

- Private files are **skipped** when knowledge entries (files or directories)
  are expanded into context exports and adapter projections — the same
  expansion used by `onecxt context export` and `onecxt adapt`.

Important limits of this mechanism:

- This is a collection filter, not access control. The file stays on disk,
  is still readable by any tool or human with filesystem access, and — if
  committed — is part of your git history like any other file.
- To keep something truly out of the repository, keep it out of tracked
  paths (git-ignored area or an untracked location) instead of relying on
  frontmatter alone.

## House rules

- Keep cross-references rooted-relative: `@knowledge/01_Compiled/one-context/conventions.md`.
  `onecxt doctor` warns on dangling references.
- Prefer editing a note over hiding it: exports are regenerated by
  `onecxt adapt`, so the canonical files are the only thing you maintain.
