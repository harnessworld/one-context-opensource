# Skill: workspace-review

Perform a quick, read-only health review of the current one-context
workspace. This skill inspects manifests and canonical sources only; it
never edits, syncs, or generates anything.

## When to use

- Before opening a PR that touches `meta/*.yaml`, `.onecxt/RULES.md`,
  `knowledge/`, `features/`, or `skills/`.
- After pulling changes whose author you cannot ask.
- When a tool's generated surfaces look stale or inconsistent.

## Steps

1. Run the workspace doctor and capture its output:

   ```bash
   onecxt doctor
   ```

2. Classify every finding:
   - **error:** a manifest or reference is broken (unknown ids, duplicate
     keys, invalid roles, missing knowledge paths referenced as errors,
     index violations, git insteadOf loops). These block merges.
   - **warning:** degraded but recoverable (missing local repo clones,
     missing rules file, dangling `@` references). Triage or explicitly
     accept each one.
3. Cross-check ownership: confirm any file the change touches is either a
   canonical source (`meta/*.yaml`, `.onecxt/RULES.md`, `knowledge/`,
   `features/`, `skills/`) or a known generated surface. Generated files
   are identified by their `GENERATED by onecxt adapt` marker; they must
   only change by regenerating with `onecxt adapt`.
4. Check the feature index once more with `onecxt doctor` output: every
   `features/**/spec.md` (outside `_template/`) must map to exactly one
   row in `features/INDEX.md`.
5. Optionally render the knowledge graph to sanity-check agent→knowledge
   wiring:

   ```bash
   onecxt doctor --graph
   ```

## Output format

Report, in this order:

- **Verdict:** pass / pass-with-warnings / fail
- **Errors:** one line each with the fix or the blocking reason
- **Warnings:** one line each with accept-or-fix recommendation
- **Ownership:** any generated file found in the change set (must be
  flagged; regenerate instead of hand-editing)

## Hard constraints

- Do not modify any file. Do not run `onecxt sync`, `onecxt adapt`, or
  any mutating command while this skill is active.
- Do not read or summarize files marked `visibility: private` in
  frontmatter, even if they appear in error messages.
